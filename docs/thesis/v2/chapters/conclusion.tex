\chapter*{Conclusion}
\addcontentsline{toc}{chapter}{Conclusion}

This thesis presented DBMS-Nautilus, a grammar-based greybox fuzzing system for automated vulnerability detection in SQLite. Built on top of Nautilus \cite{nautilus}, the system uses a structural primitives grammar that encodes SQL patterns associated with vulnerability classes without hardcoding specific proof-of-concept inputs. The grammar evolved through four versions (v3.0 to v3.3, from 449 to 520 production rules), each refined based on evidence from coverage analysis and crash investigation. The central contribution of this work is not the fuzzer itself — Nautilus provides the generation and feedback engine — but rather the grammar engineering methodology: a principled, iterative process of identifying structural deficiencies and adding targeted production rules that progressively improve the fuzzer's ability to reach vulnerability-triggering code paths.

Regarding the first research question, DBMS-Nautilus successfully rediscovered three of six target CVEs through compositional grammar generation: CVE-2020-13434 (integer overflow in \texttt{printf}), CVE-2020-9327 (null pointer dereference in generated column resolution), and CVE-2020-13871 (use-after-free in window function processing). Crucially, none of these were found by embedding proof-of-concept inputs in the grammar — the fuzzer independently composed the triggering SQL from separate structural primitives. The grammar gap analysis revealed that four of six CVEs were unreachable until version 3.2 added window function and self-referential generated column primitives, demonstrating that grammar structural coverage is the dominant factor for CVE reachability. This result validates the core premise of the structural primitives methodology: a grammar that encodes the right structural affordances enables emergent composition of vulnerability-triggering inputs without explicit contamination by known exploits.

Regarding the second research question, DBMS-Nautilus discovered seven previously unreported bug classes across 89 unique crash instances spanning four SQLite versions (3.30.1, 3.31.1, 3.32.0, and 3.32.2). These include a systematic FTS5 null pointer dereference affecting all four tested versions, pervasive float cast overflow issues with 42 distinct triggering patterns, null pointer dereferences in numeric conversion functions (\texttt{sqlite3AtoF} and \texttt{sqlite3Atoi64}), and a window function lifecycle bug in \texttt{sqlite3WindowListDelete}. The discovery of bugs across multiple SQLite versions demonstrates that the structural primitives methodology generalizes beyond the specific versions for which the grammar was initially designed: primitives added to address CVEs in 3.31.1 and 3.32.2 simultaneously triggered previously unknown bugs in 3.30.1 and 3.32.0, confirming that structural patterns rather than version-specific behavior drive the discovery.

The central insight of this work is that grammar engineering — the iterative process of analyzing coverage gaps, identifying missing structural primitives, and adding targeted production rules — is the primary driver of fuzzing effectiveness for CVE-class vulnerability discovery. The grammar defines the boundary of what the fuzzer can discover; within that boundary, coverage-guided feedback is sufficient to navigate toward bugs without requiring sophisticated sampling strategies. The grammar evolution from v3.0 to v3.3, driven by systematic evidence analysis at each step, demonstrates a practical methodology for progressively improving a fuzzing grammar's effectiveness: profile coverage to identify underrepresented non-terminals, correlate gaps with the structural patterns implicated in known vulnerability classes, extend the grammar with precisely targeted production rules, and verify that the extended grammar reaches previously inaccessible code regions. This evidence-driven feedback loop is repeatable, transferable, and independent of any specific fuzzing engine.

Several limitations bound these findings. First, all experiments target a single DBMS (SQLite \cite{sqlite}), and the results may not generalize to larger, server-based systems such as MySQL or PostgreSQL with structurally different SQL dialects. Second, the context-free grammar cannot enforce semantic constraints such as type correctness or referential integrity, meaning a substantial fraction of generated inputs are rejected at runtime as semantically invalid. Third, the sanitizer-based oracle misses non-crash bugs: CVE-2019-19646 (an infinite loop) was not detected because the oracle relies on ASan and UBSan signals rather than behavioral analysis. Fourth, the grammar design process is manual and requires domain expertise in both SQL internals and vulnerability patterns, limiting its accessibility to practitioners without background in both areas. Fifth, campaign durations of 15 to 60 minutes may be insufficient for discovering bugs that require rare compositional combinations, as evidenced by the unfound CVE-2020-13435 which requires five simultaneous structural elements across nested subqueries with specific partial-index constraints.

Four directions warrant further investigation. First, reinforcement learning integration — using a Deep Q-Network agent to learn which grammar rules to prioritize based on joint coverage and crash-frequency signals — could enable the fuzzer to allocate generation budget toward the most productive non-terminals, potentially accelerating the discovery of bugs that require rare compositional combinations without requiring manual grammar redesign. Second, cross-DBMS grammar portability should be investigated: adapting the structural primitives methodology to MySQL and PostgreSQL would test whether the layered decomposition (schema setup, stress query, validation operation, boundary function call) transfers across database engines with different internal architectures. Third, semantic-aware generation — extending the context-free grammar with type constraints and schema awareness to generate semantically valid SQL — would reduce wasted executions on inputs rejected for type errors or referential integrity violations, improving the fraction of generated inputs that reach deep semantic code paths. Fourth, automated grammar expansion using large language model-based CVE analysis to extract structural patterns from vulnerability disclosures and generate new production rules would partially automate the grammar design process that this thesis performed manually, making the structural primitives methodology accessible to practitioners without deep SQL internals expertise.
