\chapter{Introduction}
\label{chap:intro}

Database management systems are critical infrastructure in modern software. SQLite is the most widely deployed database engine in the world, embedded in every major smartphone operating system, web browser, and the Python standard library, with an estimated three trillion active installations \cite{sqlite}. A vulnerability in SQLite does not threaten a single application but potentially every application built on top of it. Despite extensive testing and code review, vulnerabilities continue to be discovered: between 2019 and 2020, six CVEs were filed against SQLite versions 3.30.1 through 3.32.2, covering integer overflow \cite{cve202013434}, null pointer dereference \cite{cve202013435}, use-after-free \cite{cve202013871}, heap buffer overread \cite{cve202015358}, uninitialized pointer \cite{cve20209327}, and infinite loop \cite{cve201919646}. The persistence of such defects in a mature codebase motivates the need for systematic automated vulnerability discovery.

Fuzzing is one of the most effective automated techniques for finding software vulnerabilities \cite{fuzzingsurvey}. Coverage-guided greybox fuzzers such as AFL \cite{afl} and libFuzzer \cite{libfuzzer} use branch coverage feedback to steer input generation toward unexplored program regions. However, byte-level mutation fuzzers fail on structured inputs like SQL: random bit flips produce parser-rejected inputs that never reach the deep query optimizer, window function engine, or virtual table logic where vulnerabilities reside. Grammar-based fuzzing addresses this by generating inputs from a context-free grammar, guaranteeing syntactic validity. Nautilus \cite{nautilus} combines grammar-based generation with coverage feedback, and other tools target databases specifically: Squirrel \cite{squirrel} adds semantic awareness, SQLsmith \cite{sqlsmith} generates random valid SQL, SQLRight \cite{sqlright} uses side-channel analysis, and Griffin \cite{griffin} performs grammar-free mutation. However, none of these systems pay systematic attention to the grammar itself --- they use general-purpose SQL grammars that treat all constructs equally, making no distinction between a trivial \texttt{SELECT 1} and a window function nested inside a correlated subquery.

This thesis presents DBMS-Nautilus, a grammar-based greybox fuzzing system for SQLite that focuses on grammar engineering as the primary lever for vulnerability discovery. The core idea is a \textit{structural primitives} grammar methodology: production rules encode SQL patterns associated with known vulnerability classes --- schema setup with generated columns, stress queries with window functions, boundary function calls with integer overflow values --- without embedding any proof-of-concept exploit input. The grammar evolved through four versions (v3.0 to v3.3, from 449 to 520 rules), each refined based on evidence from coverage profiling and crash analysis. This thesis investigates two research questions: (1) can DBMS-Nautilus rediscover existing CVEs through compositional grammar generation, and (2) can it discover previously unreported bugs beyond known CVEs. Experiments across four SQLite versions show that DBMS-Nautilus rediscovers 3 of 6 target CVEs and finds 7 new bug classes across 89 unique crash instances.

The remainder of this thesis is organized as follows. Chapter~\ref{chap:background} covers background on fuzzing, grammar-based generation, DBMS testing tools, and sanitizer oracles. Chapter~\ref{chap:method} presents the DBMS-Nautilus design: architecture, structural primitives grammar, grammar evolution, harness construction, and triage pipeline. Chapter~\ref{chap:experiments} reports the experimental evaluation structured around the two research questions. The final chapter concludes with limitations and future work.
