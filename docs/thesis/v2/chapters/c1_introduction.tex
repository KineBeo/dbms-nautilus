\chapter{Introduction}
\label{chap:intro}

Database management systems are critical infrastructure in modern software. SQLite is the most widely deployed database engine in the world, embedded in every major smartphone operating system, web browser, and the Python standard library, with an estimated three trillion active installations \cite{sqlite}. Despite extensive testing and code review, memory safety vulnerabilities continue to be discovered in SQLite at a steady pace, affecting billions of downstream devices and applications. The persistence of such defects in a mature, heavily audited codebase motivates the need for systematic automated vulnerability discovery.

Fuzzing is one of the most effective automated techniques for finding software vulnerabilities \cite{fuzzingsurvey}. Coverage-guided greybox fuzzers such as AFL \cite{afl} and libFuzzer \cite{libfuzzer} use branch coverage feedback to steer input generation toward unexplored program regions. However, byte-level mutation fuzzers fail on structured inputs like SQL: random mutations produce parser-rejected inputs that never reach deep program logic where vulnerabilities reside. Grammar-based fuzzing addresses this by generating inputs from a context-free grammar, guaranteeing syntactic validity. Nautilus \cite{nautilus} combines grammar-based generation with coverage feedback, and several tools target databases specifically: Squirrel \cite{squirrel}, SQLsmith \cite{sqlsmith}, SQLRight \cite{sqlright}, and Griffin \cite{griffin}. However, none of these systems pay systematic attention to the grammar itself --- they use general-purpose SQL grammars that treat all constructs equally, with no domain knowledge about which structural patterns are most likely to trigger vulnerabilities.

This thesis presents DBMS-Nautilus, a grammar-based greybox fuzzing system for SQLite that focuses on grammar engineering as the primary lever for vulnerability discovery. The core idea is a \textit{structural primitives} grammar methodology: production rules encode SQL patterns associated with vulnerability classes --- schema setup with generated columns, stress queries with window functions, boundary function calls with integer overflow values --- without embedding any proof-of-concept exploit input. The grammar evolved through four versions (v3.0 to v3.3, from 449 to 520 rules), each refined based on evidence from coverage profiling and crash analysis. Experiments across four SQLite versions show that DBMS-Nautilus rediscovers 3 of 6 target CVEs through compositional grammar generation and finds 7 previously unreported bug classes across 89 unique crash instances.

The remainder of this thesis is organized as follows. Chapter~\ref{chap:background} covers background on fuzzing, grammar-based generation, DBMS testing tools, and sanitizer oracles. Chapter~\ref{chap:method} presents the DBMS-Nautilus design: architecture, structural primitives grammar, grammar evolution, harness construction, and triage pipeline. Chapter~\ref{chap:experiments} reports the experimental evaluation structured around two research questions: whether DBMS-Nautilus can rediscover known CVEs, and whether it can find new bugs beyond known vulnerabilities. The final chapter concludes with limitations and future work.
